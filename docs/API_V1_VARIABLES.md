# Patra Corporate API: Variables & Schema Reference

This document provides a detailed breakdown of all variables and data parameters collected or used by the Patra Corporate API (v1).

---

## 1. Core Staff Profile (Variables Collected)

These fields are gathered when a staff record is created or updated. They are typically mapped from your existing HRIS or database.

| Field Name | JSON Key | Data Type | Required | Description |
| :--- | :--- | :--- | :--- | :--- |
| **Full Name** | `display_name` | String | **Yes** | The employee's name as it will appear on the card. |
| **Email** | `email` | String | **Yes** | Corporate email address. Used for identification & notifications. |
| **Job Title** | `job_title` | String | **Yes** | Official designation (e.g., Marketing Director). |
| **Phone** | `phone` | String | No | Contact number. |
| **Avatar URL** | `avatar_url` | String (URL) | No | Link to a high-quality profile photo (processed for ID card). |
| **Bio** | `bio` | String | No | Short professional summary. |
| **Department** | `department` | String | No | Internal department name. |
| **Location** | `location` | String | No | Office location or city. |

---

## 2. API Response Variables (Data Returned)

When you create or fetch a staff record via the API, Patra returns the following variables:

| Field Name | JSON Key | Data Type | Description |
| :--- | :--- | :--- | :--- |
| **Record ID** | `id` | UUID | Unique internal identifier for the invitation/record. |
| **Staff ID** | `staff_id` | String | Human-readable ID generated by Patra (e.g., `PAT-001`). Used in URLs. |
| **Card URL** | `card_url` | URL | **The direct live link to the digital ID card.** |
| **Status** | `status` | String | Current state: `invited`, `joined`, or `rejected`. |
| **Approval** | `is_approved` | Boolean | Whether the staff member has been verified by the company admin. |

---

## 3. Configuration & Metadata

### Metadata (Custom Fields)
You can attach arbitrary JSON to a staff record using the `metadata` field. This is useful for storing internal IDs or custom flags.

```json
{
  "metadata": {
    "internal_employee_id": "EMP-456",
    "region": "NA-WEST"
  }
}
```

### Design Overrides
If you want a specific staff member to use a different ID card design than your company default, provide the `design_id`.

```json
{
  "design": "card_template_id_here"
}
```

---

## 4. Webhook Payload Variables

When a webhook is triggered (e.g., `staff.added`), you will receive a payload containing:

| Variable | Description |
| :--- | :--- |
| `event` | The type of event (`staff.added`, `staff.updated`). |
| `timestamp` | UNIX timestamp of when the event occurred. |
| `payload` | The full staff record object. |

---

## 5. React Developer Integration (Quick Summary)

### Required Setup
1.  **Request Keys**: Get your `pk_live_...` key from the Patra Dashboard.
2.  **Environment Variables**: Save your key in `.env.local` as `VITE_PATRA_API_KEY`.
3.  **Proxying Requests**: In production, always perform API calls server-side (Next.js server actions or API routes) to avoid leaking the private key.

---

### Variable Distribution & Distribution Flow
1. **INPUT**: You send `display_name`, `email`, `job_title` to the API.
2. **PROCESS**: Patra validates the key, generates a `staff_id`, and creates the card.
3. **OUTPUT**: Patra returns `card_url`.
4. **CONNECT**: Distribute the `card_url` to the employee via your internal communication tools (Slack, Email, SMS).
